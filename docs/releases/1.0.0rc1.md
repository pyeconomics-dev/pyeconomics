# pyeconomics 1.0.0rc1 - 2026-11-19

This is the release candidate for pyeconomics 1.0.0. Its public API is frozen
([`docs/public-api.md`](https://github.com/pyeconomics-dev/pyeconomics/blob/v1.0.0rc1/docs/public-api.md)),
and 1.0.0 will be this candidate with only its version changed, once it has run
in production for seven days and passed the launch readiness gate. If the gate
finds a problem, the next candidate is 1.0.0rc2.

It is a pre-release: `pip install` installs it only when asked. Plain
`pip install pyeconomics` still installs 0.2.6, the stable release, until 1.0.0
ships. Python 3.12 or later is required.

```sh
python -m pip install --pre "pyeconomics==1.0.0rc1"
python -m pip install --pre "pyeconomics[econometrics,plot,server,mcp]==1.0.0rc1"
uvx --from "pyeconomics[mcp]==1.0.0rc1" pyeconomics mcp
```

The web app on your own machine:

```sh
python -m pip install --pre "pyeconomics[app]==1.0.0rc1"
pyeconomics serve
```

Then open `http://127.0.0.1:8000/`.

## What 1.0 contains

| | Count |
|---|---|
| Models (permanent ids) | 50, across 13 domains |
| Data providers | 31 |
| Catalog concepts | 171 |
| Web app pages | 285 |
| MCP tools | 21 (5 discovery tools and 16 model tools) |
| Problem types | 33 |

- **The model engine.** Every model is a pure function with typed inputs and
  outputs, units and bounds, cited formulas, at least three cited golden
  cases and property tests. Every result carries a manifest that makes it
  reproducible. Rates and percentages are decimals: `0.05` means 5%.
- **The data platform.** Thirty-one providers behind one catalog of concepts,
  live bindings that read data as it was published on a date, a local cache
  that follows each source's terms, and a key chain (environment, `.env`,
  system keyring) that never prints a key.
- **Five surfaces, one set of bytes.** The Python API, the `pyeconomics`
  command line, the REST API (`pyeconomics serve`), the MCP server
  (`pyeconomics mcp`) and the web app all return the same canonical JSON for
  the same inputs, and every failure is a problem from one table.
- **Exports and bundles.** CSV, XLSX, Parquet, Arrow and JSON, each carrying
  the data's attributions and notices, and reproducibility bundles that rerun a
  result and check its hash.
- **The web app.** A page for every model with its formulas, a calculator and
  code for every surface; a data explorer with a page for every concept; search,
  domain sections, a coverage matrix and a syllabus seed; legal and trust pages.
  The hosted site serves the sources whose terms allow it, from a daily
  snapshot; locally, `pyeconomics[app]` serves the same site with your own keys
  and the whole catalog.
- **Guides.** Tutorials, how-to guides, a migration guide from 0.2.x, a gallery,
  in-browser examples and finance tutorials.

## New since 1.0.0b1

- The web app, its hosted data plane and its local wheel, `pyeconomics-app`,
  published with `pyeconomics` at the same version through one Trusted
  Publishing exchange.
- The data explorer, and a series transform (`transform=`) on every series
  surface.
- What each formula's symbols stand for, on every model (756 definitions).
- The guides above.
- The public API inventory and its test.
- Fixes, among them: the hosted copy of each Bureau of Labor Statistics series
  holds its whole history; FRED series cite their originating source as FRED's
  terms ask; the New York Fed's reference rates carry every notice its terms
  require.

The [changelog](https://github.com/pyeconomics-dev/pyeconomics/blob/v1.0.0rc1/CHANGELOG.md)
lists every change. No model's outputs changed, and the permanent ledgers still
hold the same 50 model, 31 provider and 171 concept ids.

## How it was released

- **Rehearsal.** `v1.0.0rc1.dev1`, on `main` at
  `c9dfc4c521f5800a7bc643943a398ec2778ef030`, published both distributions to
  TestPyPI (release run
  [44607789496](https://github.com/pyeconomics-dev/pyeconomics/actions/runs/44607789496),
  pyeconomics-app's first upload). Each file carries a PEP 740 provenance
  naming this repository, `release.yml` and its environment. The pyeconomics
  wheel and sdist equal a local `uv build --no-config` of the commit byte for
  byte. The pyeconomics-app wheel differs from a local Windows build only where
  the build machine shows: example results computed by NumPy differ in their
  last digits (at most 2.4e-8 relative, on the output gap's HP filter), the
  licence page links the source of the Pagefind binary installed on that
  platform, and the search index follows those pages. Clean installs of the
  core, `[econometrics,plot]`, `[server]`, `[app]` with `pyeconomics serve`, and
  `[mcp]` through uvx with the MCP Inspector all passed.
- **Release.** The `v1.0.0rc1` tag publishes both distributions to PyPI with
  provenances, deploys the candidate to production behind Cloudflare Access,
  where it is not indexed, and publishes the MCP Registry entry at 1.0.0rc1
  (stdio only, until the hosted endpoint is public).
- **Soak.** Seven days in production, during which only security fixes merge.
  It passes with no unexplained server error, at least 99.5% uptime on the
  status page, every scheduled snapshot run green, every Sentry issue triaged,
  the production health check green, spend inside the budget and no Critical or
  High security finding open.

## Known limitations

- **The hosted site opens at 1.0.0.** Until the launch, pyeconomics.dev is
  behind Cloudflare Access and not indexed.
- **Hosted data is what the sources allow.** The hosted site and API serve only
  sources whose terms allow it, from a snapshot at most a day old. FRED,
  ALFRED and other library-only sources run on your own machine, with your own
  keys where a source asks for one. Permission requests to the IMF and the
  Federal Reserve Banks of Atlanta and Cleveland are open
  ([#311](https://github.com/pyeconomics-dev/pyeconomics/issues/311),
  [#313](https://github.com/pyeconomics-dev/pyeconomics/issues/313),
  [#314](https://github.com/pyeconomics-dev/pyeconomics/issues/314)); their data
  stays library-only until they answer.
- **The MCP tool list is large**
  ([#197](https://github.com/pyeconomics-dev/pyeconomics/issues/197)): its 21
  tools cost an agent about 69k tokens of context. Slimmer schemas that keep
  every tool name and its validation are a compatible 1.x change.
- **Findings from the site's last review round**, none of which stopped a task:
  search ([#371](https://github.com/pyeconomics-dev/pyeconomics/issues/371)),
  phone layout ([#372](https://github.com/pyeconomics-dev/pyeconomics/issues/372)),
  the calculator's errors and results
  ([#373](https://github.com/pyeconomics-dev/pyeconomics/issues/373)), series
  pages ([#374](https://github.com/pyeconomics-dev/pyeconomics/issues/374)),
  wording ([#375](https://github.com/pyeconomics-dev/pyeconomics/issues/375)),
  the developer snippets
  ([#376](https://github.com/pyeconomics-dev/pyeconomics/issues/376)), the time
  value calculator's opening example
  ([#377](https://github.com/pyeconomics-dev/pyeconomics/issues/377)) and a late
  font on some Linux desktops
  ([#359](https://github.com/pyeconomics-dev/pyeconomics/issues/359)).
- **A nullable list field's schema** gives its length bounds as `minLength` and
  `maxLength`, which JSON Schema applies only to text
  ([#245](https://github.com/pyeconomics-dev/pyeconomics/issues/245)); the
  model still enforces them.
- **Python 3.15:** `econometrics.garch` needs `arch`, which has no CPython 3.15
  wheel yet ([#154](https://github.com/pyeconomics-dev/pyeconomics/issues/154)).
- **Pyodide:** the in-browser examples use models that need no data; the
  transport and the cache have not run under Pyodide
  ([#114](https://github.com/pyeconomics-dev/pyeconomics/issues/114),
  [#116](https://github.com/pyeconomics-dev/pyeconomics/issues/116)), and the
  transport ignores proxy variables
  ([#113](https://github.com/pyeconomics-dev/pyeconomics/issues/113)).
- **Sources' own gaps and quirks:** CBO's archive
  ([#142](https://github.com/pyeconomics-dev/pyeconomics/issues/142),
  [#195](https://github.com/pyeconomics-dev/pyeconomics/issues/195)), the New
  York Fed's EFFR history
  ([#135](https://github.com/pyeconomics-dev/pyeconomics/issues/135),
  [#196](https://github.com/pyeconomics-dev/pyeconomics/issues/196)), BLS's
  three-year default window for library reads
  ([#141](https://github.com/pyeconomics-dev/pyeconomics/issues/141)) and its
  October 2025 gap
  ([#158](https://github.com/pyeconomics-dev/pyeconomics/issues/158)), early
  Saturday sessions in daily factor files
  ([#159](https://github.com/pyeconomics-dev/pyeconomics/issues/159)), empty
  windows across providers
  ([#131](https://github.com/pyeconomics-dev/pyeconomics/issues/131)), a
  source's maintenance page
  ([#163](https://github.com/pyeconomics-dev/pyeconomics/issues/163)), and
  binary noise in rates a source publishes as percentages
  ([#256](https://github.com/pyeconomics-dev/pyeconomics/issues/256)).
- **Libraries' behaviour:** statsmodels' Engle-Granger coefficients and
  `coint_johansen` with no lagged differences
  ([#155](https://github.com/pyeconomics-dev/pyeconomics/issues/155),
  [#156](https://github.com/pyeconomics-dev/pyeconomics/issues/156)), and
  another thread's warnings during a wrapped fit
  ([#174](https://github.com/pyeconomics-dev/pyeconomics/issues/174)).
- **The cache** keys entries without a parser version
  ([#136](https://github.com/pyeconomics-dev/pyeconomics/issues/136)).
- **Property tests under the development profile** find counterexamples at
  bounds the CI profile does not draw
  ([#112](https://github.com/pyeconomics-dev/pyeconomics/issues/112),
  [#137](https://github.com/pyeconomics-dev/pyeconomics/issues/137),
  [#139](https://github.com/pyeconomics-dev/pyeconomics/issues/139),
