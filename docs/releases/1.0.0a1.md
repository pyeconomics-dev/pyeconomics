# pyeconomics 1.0.0a1 - 2026-10-13

This is the first alpha of the rebuilt Python model library. It replaces the
0.2.x API; it does not yet include live data, a CLI, REST API, MCP server or
web application. **Pre-releases carry no stability promise** under
[ADR-0003](https://github.com/pyeconomics-dev/pyeconomics/blob/v1.0.0a1/docs/adr/0003-versioning-and-deprecation.md). Inputs, outputs and
Python APIs may change between pre-releases. The 0.2.6 stable release remains
available and receives security fixes until 1.0.0.

Install the alpha explicitly in a separate environment:

```sh
python -m pip install --pre 'pyeconomics==1.0.0a1'
python -m pip install --pre 'pyeconomics[econometrics,plot]==1.0.0a1'
```

[PyPI release](https://pypi.org/project/pyeconomics/1.0.0a1/).
Plain `pip install pyeconomics` continues to install stable 0.2.6.

The supported Python floor is 3.12. Rates and percentages are decimals:
`0.05` means 5%. See the [1.0 documentation preview](https://pyeconomics.readthedocs.io/en/main/)
for typed inputs, bounds, assumptions, limitations, formulas and examples.
The `main` preview can advance beyond this alpha; stable/latest still serve
0.2.6 during the pre-release series.

## What the alpha contains

One registry exposes 32 data-free model families across 11 domains. Every
family has a generated model card, cited golden cases and property tests.

| Domain | Model ids |
|---|---|
| Foundations | `foundations.time_value`, `foundations.returns`, `foundations.risk_statistics`, `foundations.hypothesis_tests`, `foundations.simulation` |
| Fixed income | `fixed_income.bond_pricing`, `fixed_income.money_market`, `fixed_income.curve_bootstrap`, `fixed_income.duration`, `fixed_income.convexity`, `fixed_income.credit_spread` |
| Derivatives | `derivatives.forwards`, `derivatives.interest_rate_swap`, `derivatives.black_scholes_merton`, `derivatives.binomial_tree`, `derivatives.futures_fx_options` |
| International | `international.parity_conditions` |
| Equity | `equity.dividend_discount`, `equity.free_cash_flow` |
| Corporate | `corporate.cost_of_capital`, `corporate.capital_budgeting`, `corporate.leverage` |
| Accounting | `accounting.financial_ratios`, `accounting.scoring_models` |
| Portfolio | `portfolio.mean_variance`, `portfolio.utility` |
| Performance | `performance.return_measurement`, `performance.risk_adjusted`, `performance.brinson_attribution` |
| Risk | `risk.value_at_risk`, `risk.var_backtest` |
| Econometrics | `econometrics.ols` |

`pyeconomics.run` returns validated outputs, recorded warnings and a
reproducible provenance manifest. Results export to canonical JSON, pandas,
Polars, Arrow and Parquet; install Polars or pyarrow separately for those
optional exports. `run_batch` processes bounded batches. `Result.plot()`
uses the `plot` extra. OLS requires the `econometrics` extra; without it the
error names the missing extra. These extras are also included in `all`.

The core provides units and tolerances, compounding, seeded randomness,
root finding, date arithmetic, six day-count conventions, coupon schedules,
holiday calendars and shared cash-flow, descriptive and curve calculations.
Models perform no I/O; users supply every input.

## Corrections before the alpha

Version 2 of bond pricing, duration and convexity corrects the US 30/360
long first-period timing error found during readiness
([#89](https://github.com/pyeconomics-dev/pyeconomics/issues/89)); see the
[public erratum](https://github.com/pyeconomics-dev/pyeconomics/blob/v1.0.0a1/docs/errata.md).

Python 3.15 final joins the CI matrix on Ubuntu, Windows and macOS with its
package classifier ([#65](https://github.com/pyeconomics-dev/pyeconomics/issues/65)).
The minimum Python version remains 3.12.

## Known limitations

The corrected dev3 candidate passed the TestPyPI rehearsal and received the
maintainer's GO on 2026-10-12; see the
[readiness evidence](https://github.com/pyeconomics-dev/pyeconomics/blob/v1.0.0a1/docs/releases/1.0.0a1-readiness.md).
The Python floor was re-checked on 2026-10-13 and remains 3.12.
All 32 model ids are recorded in the permanent released-id ledger.

- This is a substantial rewrite. The four FRED-backed 0.2.x monetary-policy
  rules are not part of this alpha; data providers and that suite arrive in
  Phase 3. Keep legacy workloads in a separate environment.
- Model bounds and refusal rules are deliberate. Undefined quantities may
  return null with a warning or raise a documented error. Model cards state
  each formula's conventions and statistical assumptions.
- Shared IRR can miss a root exactly at either inclusive bracket endpoint
  (`-0.99` or `10`); see [issue #85](https://github.com/pyeconomics-dev/pyeconomics/issues/85).
  Avoid those endpoint cases pending a fix.
- Numeric unit aliases can accept booleans as numbers; supply numeric values
  explicitly ([#75](https://github.com/pyeconomics-dev/pyeconomics/issues/75)).
  Registry validation does not yet reject every numeric `Literal` lacking a
  unit ([#81](https://github.com/pyeconomics-dev/pyeconomics/issues/81)).
- No live data, generated service surfaces, syllabus crosswalks or stability
  guarantee ships in this alpha. Outputs are formula results for supplied
  inputs and must be checked independently.
