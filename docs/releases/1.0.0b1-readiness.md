# `1.0.0b1` Release Readiness Gate

`pyeconomics 1.0.0b1` (the Phase 4 beta pre-release delivering the CLI,
tabular/document exports and reproducibility bundles, the FastAPI REST server
and generated TypeScript/Python clients, hosted mode, the MCP server with MCP
Apps and official MCP Registry metadata, cross-surface parity, the optional AI
narrative, the hardened multi-stage container, and the staging deployment on
Google Cloud Run behind Cloudflare Zero Trust Access and a Cloudflare Worker).
Every section records the concrete commands executed, the observed outputs, and
the disposition of each requirement before the `1.0.0b1` production pre-release
(Phase 4 Step 15).

## 7. The REST API and hosted mode

Verified in a clean `[server]` virtual environment from TestPyPI, in
`tests/server/`, and in CI (`api-fuzz` and `clients` jobs):

- **Clean-venv `pyeconomics serve`:** Started `pyeconomics serve --port <port> --workers 1`
  on `127.0.0.1` from the TestPyPI wheel; `GET /version` returned
  `{"git_sha": "unknown", "mode": "local", "pyeconomics": "1.0.0b1.dev1"}` and
  `POST /v1/models/foundations.time_value/run` returned HTTP `200` with
  `result_sha256 == "7f6efea8af93521b9a501af064ed2d4eb281c029ac03a5c86b79156a75ea01e7"`.
- **Worker pool & framing (`server.pool`, `server.work`):** All model runs and
  series fetches execute in spawned worker processes communicating via length-prefixed
  canonical JSON headers and raw payload bytes (never `pickle`), with worker
  modules importing no web framework (`tests/server/test_server_layering.py`).
- **Host & origin protection:** Local mode refuses non-loopback `Host` headers
  with `421` (`host-not-allowed`) unless `--allow-remote` is passed.
- **Hosted-mode guards (`server.edge`, `server.limits`, `server.run_cache`):**
  - `_Guard` verifies `X-Pyeconomics-Edge` in constant time (`hmac.compare_digest`
    over SHA-256 digests) before trusting `CF-Connecting-IP` or touching Redis.
  - Per-IP moving-window rate limits (`60/minute` runs, `30/minute` series,
    `120/minute` metadata) backed by Upstash Redis over TLS (`rediss://`),
    returning `503` (`limits-unavailable`) for runs and series if Redis is
    unreachable.
  - `GET /v1/models/<id>/run?inputs=...` caches cacheable results in memory with
    `ETag: W/"<result_sha256>"`, `304 Not Modified` on `If-None-Match`, and
    `Cache-Control`; `POST` runs and problems always carry `Cache-Control: no-store`.
- **OpenAPI 3.1 & generated clients:** `GET /openapi.json` is snapshotted by
  digest; `ci.yml`'s `clients` job generates and smoke-tests both the TypeScript
  client (`@hey-api/openapi-ts` in `tools/node`) and the Python client
  (`openapi-python-client`), and `api-fuzz` fuzzes the schema with Schemathesis.

## 13. Known limitations and open issues

### Architectural scope boundaries for `1.0.0b1` (by design)

1. **Hosted `/v1/series/<target>` fetches upstream per request until Phase 5:**
   In Phase 4 (`1.0.0b1`), hosted `/v1/series/<target>` fetches hosted-safe
   public-domain series through the worker pool under the `30/minute` per-IP
   rate limit and `/tmp` container SQLite cache. Pre-built Cloudflare R2
   Parquet snapshots arrive in Phase 5.
2. **Hosted mode serves only keyless `hosted-safe` data and disables AI narratives:**
   Library-only, keyed, contact-required, and opt-in sources (`fred`, `bls` v2,
   `bea`, `census`, `sec_edgar`, `yfinance`, etc.) and `--narrate` /
   `pyeconomics.ai.narrate` are refused in hosted mode (`403`) with the exact
   local CLI command (`budgets.local_command`). Hosted API keys and multi-tenant
   billing belong to Phase 8.
3. **CPython 3.15 wheel markers on `arch` and `fuzz`:** `arch>=8.0`
   (`econometrics` extra, #154) and `pyyaml` (`fuzz` dev group, #182) carry
   `python_version < '3.15'` markers under the Wheel rule until upstream ships
   CPython 3.15 wheels.
