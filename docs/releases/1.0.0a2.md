# pyeconomics 1.0.0a2 - draft

> Draft for Phase 3 Step 19. Step 19 sets the release date in the title,
> removes this note and publishes the notes as the GitHub pre-release. The
> rehearsed candidate is `1.0.0a2.dev1`; see the
> [readiness evidence](https://github.com/pyeconomics-dev/pyeconomics/blob/v1.0.0a2/docs/releases/1.0.0a2-readiness.md).

This is the second alpha of the rebuilt library. It adds the data platform:
31 free data providers, a semantic catalog of 171 concepts, live bindings that
read the data as it was published on a past date, and 18 new model families,
the monetary-policy suite among them. **Pre-releases carry no stability
promise** under
[ADR-0003](https://github.com/pyeconomics-dev/pyeconomics/blob/v1.0.0a2/docs/adr/0003-versioning-and-deprecation.md).
Inputs, outputs, manifests and Python APIs may change between pre-releases.
The 0.2.6 stable release remains available and receives security fixes until
1.0.0.

Install the alpha explicitly in a separate environment:

```sh
python -m pip install --pre 'pyeconomics==1.0.0a2'
python -m pip install --pre 'pyeconomics[keyring,sdmx,econometrics,plot]==1.0.0a2'
```

[PyPI release](https://pypi.org/project/pyeconomics/1.0.0a2/).
Plain `pip install pyeconomics` continues to install stable 0.2.6.

The supported Python floor is 3.12. Rates and percentages are decimals:
`0.05` means 5%. See the [1.0 documentation preview](https://pyeconomics.readthedocs.io/en/main/)
and its [data sources and keys guide](https://pyeconomics.readthedocs.io/en/main/data/index.html).

## Data sources and keys

`pyeconomics.data.get` reads a catalog concept (`us.inflation.cpi.yoy`) or a
provider's own series (`bls:CUUR0000SA0`). The resolver picks the source from
your mode, your keys and your extras, and every frame and manifest carries the
source's licence class, attribution, required notice and terms page.

| Group | Provider ids |
|---|---|
| US statistical agencies | `fred` (FRED and ALFRED), `bls`, `bea`, `census` |
| US rates and filings | `treasury`, `fed_board`, `nyfed`, `sec_edgar`, `openfigi` |
| International (SDMX and REST) | `imf`, `oecd`, `ecb`, `bis`, `eurostat`, `world_bank`, `dbnomics` |
| Research | `philadelphia_fed`, `atlanta_fed`, `cleveland_fed`, `cbo`, `penn_world_table` |
| Asset pricing and markets | `ken_french`, `shiller`, `damodaran`, `aqr`, `hou_xue_zhang`, `jkp`, `open_source_asset_pricing`, `cboe`, `coin_metrics`, `yfinance` |

- **Keys.** FRED, BEA and Census need your own free key; BLS and OpenFIGI work
  without one (BLS reads API v1 keyless, with lower limits). SEC EDGAR needs
  your contact for its User-Agent. Keys are read from `<PROVIDER>_API_KEY`, a
  `.env` file in your configuration directory or the OS keyring (the `keyring`
  extra), and never reach a log, an error, a manifest, the cache or an export.
- **Extras.** `sdmx` adds IMF, OECD, ECB, BIS and Eurostat; `yfinance` adds
  Yahoo Finance, which stays off until you enable it; `keyring` reads keys from
  the OS keyring; `all` includes every extra.
- **Terms.** Each source's terms are yours to accept. Sources whose terms bar
  storage, FRED and ALFRED among them, are never written to disk; others are
  cached under their terms. Hosted mode (`PYECONOMICS_MODE=hosted`) reads only
  sources classed `hosted-safe`.

## Live bindings and real time

`pyeconomics.bind(model_id, as_of=...)` resolves a model's declared bindings and
`pyeconomics.run` runs the result. With an `as_of` date a binding reads the
vintage published by then (ALFRED for FRED series, the Philadelphia Fed's
real-time data set, CBO's report of the day). Where no usable source keeps
vintages, it reads the latest data and says so: the field's record and the
result's warnings carry `revised_data`. Overrides replace a bound value and are
recorded as user-supplied by field, never by value.

## New models

| Domain | Model ids |
|---|---|
| Macroeconomics | `macro.policy_rule`, `macro.neutral_rate`, `macro.output_gap`, `macro.phillips_curve`, `macro.okun_law`, `macro.solow_growth`, `macro.debt_dynamics`, `macro.recession_probability` |
| Fixed income | `fixed_income.curve_fitting`, `fixed_income.interest_rate_tree` |
| Equity | `equity.implied_risk_premium`, `equity.cape` |
| Asset pricing | `asset_pricing.factor_regression`, `asset_pricing.factor_model_tests` |
| Portfolio | `portfolio.black_litterman`, `portfolio.risk_based_allocation` |
| Econometrics | `econometrics.garch`, `econometrics.time_series` |

`macro.policy_rule` brings back the 0.2.x monetary-policy rules (Taylor 1993
and 1999, balanced approach, inertial, first-difference, ELB-adjusted and
forecast-based) on the new engine, with pluggable r* and gap measures. The
registry now holds 50 model families in 13 domains, each with a model card,
cited golden cases and property tests. `econometrics.garch` needs the
`econometrics` extra, which installs arch only below Python 3.15 for now (see
known limitations).

## Breaking changes

- **Manifest schema 2.** `schema_version` is 2 and `data_sources` holds one
  `DataSource` record per bound field, sorted by field. A record holds the
  provider, series, concept, vintage or real-time period, observation window,
  transforms, retrieval time, licence class, attribution, notice, terms page,
  `llm_use`, cache use and warnings; never a request URL, host, path or key.
  `result_sha256` and `inputs_sha256` keep their definitions, so a model that
  reads no data has the same hashes as in 1.0.0a1.
- A bind of a model with several calculations needs `calculation=...`.
- Numeric unit markers reject booleans, and date fields reject numeric epoch
  timestamps ([#75](https://github.com/pyeconomics-dev/pyeconomics/issues/75)).
  Registry validation requires units and bounds on numeric `Literal` fields
  ([#81](https://github.com/pyeconomics-dev/pyeconomics/issues/81)).

## Corrections

`foundations.time_value`, `corporate.capital_budgeting` and
`performance.return_measurement` advance from model version 1 to 2: shared IRR
now recognizes a root at either inclusive bracket endpoint
([#85](https://github.com/pyeconomics-dev/pyeconomics/issues/85)); see the
[public erratum](https://github.com/pyeconomics-dev/pyeconomics/blob/v1.0.0a2/docs/errata.md).
`performance.brinson_attribution` no longer raises a math domain error for a
period return within rounding of -100%; inputs that ran before give the same
results. Model ids are unchanged.

## Known limitations

- Source availability is outside pyeconomics' control. A source's maintenance
  page surfaces as a parse error rather than an outage
  ([#163](https://github.com/pyeconomics-dev/pyeconomics/issues/163)); the
  resolver fails over only to a candidate that delivers the same concept.
  No setting yet turns off one provider
  ([#162](https://github.com/pyeconomics-dev/pyeconomics/issues/162)): rebind
  a field with `concepts=` or name a provider series instead.
- `econometrics.garch` is unavailable on Python 3.15 until arch publishes
  CPython 3.15 wheels; the model names the gap
  ([#154](https://github.com/pyeconomics-dev/pyeconomics/issues/154)).
- `econometrics.time_series`' default profile cannot bind windows that end on or
  after October 2025, because BLS published no October 2025 CPI or
  unemployment rate and a binding never fills a gap
  ([#158](https://github.com/pyeconomics-dev/pyeconomics/issues/158)).
- BLS answers a whole-history request with about three years, and CBO's
  provider holds potential GDP from 2021 only, so long windows fall back to
  other sources or fail ([#141](https://github.com/pyeconomics-dev/pyeconomics/issues/141),
  [#142](https://github.com/pyeconomics-dev/pyeconomics/issues/142)).
- The cache key carries no parser version: clear the cache after upgrading if a
  provider's parsing changed ([#136](https://github.com/pyeconomics-dev/pyeconomics/issues/136)).
- The HTTP transport ignores proxy environment variables, and neither the
  transport nor the cache has run under Pyodide
  ([#113](https://github.com/pyeconomics-dev/pyeconomics/issues/113),
  [#114](https://github.com/pyeconomics-dev/pyeconomics/issues/114),
  [#116](https://github.com/pyeconomics-dev/pyeconomics/issues/116)).
- `core.library_warnings` uses process-global warning filters: run models that
  wrap statsmodels or arch from one thread at a time
  ([#157](https://github.com/pyeconomics-dev/pyeconomics/issues/157)).
- The Engle-Granger critical values use statsmodels' MacKinnon (2010)
  coefficients, one of which differs from the paper by 2.8e-4 at T = 199; the
  Johansen test requires at least one lagged difference
  ([#155](https://github.com/pyeconomics-dev/pyeconomics/issues/155),
  [#156](https://github.com/pyeconomics-dev/pyeconomics/issues/156)).
- `portfolio.mean_variance`'s frontier can overflow for expected returns that
  differ by almost nothing
  ([#151](https://github.com/pyeconomics-dev/pyeconomics/issues/151)).
- No CLI, REST API, MCP server or web application ships in this alpha; they
  arrive in Phase 4. Outputs are formula results for the data and inputs used
  and must be checked independently.
