# 1.0.0a2 Readiness Gate — dev1

This gate evaluates the second PyPI alpha: the first release that reads users'
keys and fetches their data. Nothing in this step publishes to PyPI. A
maintainer decision is required before Phase 3 Step 19 can publish.

- **Gate date:** 2026-10-21 (America/New_York).
- **Candidate:** `1.0.0a2.dev1`, origin/main commit
  `610da6f122d15f3ff758b68e7f4a1f8698a57777` (PR #160).
- **Rehearsal tag:** `v1.0.0a2.dev1`, pushed at the candidate commit with the
  maintainer's approval; release run and smoke succeeded.
- **Baseline:** PyPI pre-release `1.0.0a1`; PyPI stable `0.2.6`. No production
  upload is authorized here.
- **Method:** every command below was run during this gate unless explicitly
  marked pending. PASS means the evidence was observed; FAIL marks an unmet
  requirement. Scratch scripts and logs are in ignored `dev/step18/`. Installs
  use `--no-config` to exclude the machine's private package index. No key,
  contact, environment listing or key-bearing response is recorded: key checks
  report presence by name only.
- **Frozen candidate:** the maintainer approved holding the seven open
  Dependabot pull requests (#98–#103, #161) until Step 19 publishes, so `main`
  stays at the rehearsed commit. A changed candidate needs a fresh rehearsal
  and GO.

## 12. Rollback

This is the procedure for a broken published alpha, not an instruction to
roll back during the gate. Owner: Nathan Ramos, CFA.

| Action | Command or place | Owner | Review result |
|---|---|---|---|
| Stop new unpinned alpha installs | PyPI Manage → pyeconomics → 1.0.0a2 → Yank, with a reason naming the defect. Never delete files | Maintainer | PASS (procedure reviewed) |
| Verify the yank | `curl -H 'Accept: application/vnd.pypi.simple.v1+json' https://pypi.org/simple/pyeconomics/`; both files show the yank reason; a fresh `--pre` resolution falls back to `1.0.0a1` | Agent | PASS (procedure reviewed) |
| Rehearse the fix | Fix branch from `main`, version `1.0.0a2.post1.dev1`; tag it on merged `main` and let `release.yml` publish it to TestPyPI | Agent prepares; maintainer approves the tag | PASS (the verify pattern accepts `.postN.devN`) |
| Publish the correction | Release PR sets `1.0.0a2.post1`; tag `v1.0.0a2.post1` on merged `main`; approve the `pypi` deployment; clean install, provenance and smoke checks | Maintainer approves; agent verifies | PASS (the verify pattern accepts `.postN`) |
| Disable a failing provider | Read `pyeconomics.data.config.Settings` and the providers' `check_configuration` hooks | User or maintainer | GAP: no configuration switch turns off one provider; the only source switch is yfinance's opt-in ([#162](https://github.com/pyeconomics-dev/pyeconomics/issues/162), `architecture`). Mitigations without a release are listed below; the maintainer's decision in §14 covers it |
| Record the incident | `gh release edit v1.0.0a2 --notes-file <reviewed notes>`; link the correction; errata if a number changed | Agent, with maintainer-reviewed wording | PASS (procedure reviewed) |

Exact pins can still install a yanked version; consumers must change them.

Until #162 adds a switch, a failing or misparsing source is handled without a
release by: the resolver's fail-over, which passes over a candidate that raises
and tries the next one that delivers the same concept (observed in §6 when FRED
was down: `bea` skipped, `fred` refused); `bind(..., concepts={field: other})`
to rebind a field, or `data.get("<provider>:<series>")` to name a source;
`configure(offline=True)` to serve only the cache (never FRED or DBnomics, which
are not stored); hosted mode, which refuses every source not classed
`hosted-safe`; and removing the `sdmx` or `yfinance` extra. A source that
returns wrong values rather than raising needs the yank and `.postN` path above.
